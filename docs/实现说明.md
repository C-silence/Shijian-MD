# 拾简 · v1 实现说明

本文记录 v1 的落地方式、关键取舍与验证情况。需求与视觉规范以 `项目设计文档.md` 为准。

---

## 1. 分层

```
MainActivity  ──  Intent(VIEW/EDIT/SEND) ──┐
                                           ▼
AppRoot ── ShijianTheme(spec) ── MdSurface ── DocumentScreen / HomeScreen / SettingsScreen
                                                   │
                            AppViewModel ──────────┤  状态：选中文档、模式、解析结果、保存
                              │        │
                    data/     │        └── md/   解析：commonmark → MdBlock 列表
             SettingsStore    │            MdParser / MdModel
             RecentStore      │
             DocIo ───────────┘  SAF 读写 + 编码嗅探
```

Compose 侧不持有业务状态：`AppViewModel` 用 `mutableStateOf` 暴露 `doc / parsed / mode / toast`，UI 只读不写。

## 2. 解析管线（`md/MarkdownParser.kt`）

1. **预处理**：把 `<kbd>x</kbd>` 换成行内代码，避免为键帽单独造节点；其余 HTML 原样保留。
2. **解析**：commonmark 0.30 + 四个扩展（表格、删除线、任务列表、YAML front matter），并开启 `IncludeSourceSpans.BLOCKS_AND_INLINES` 以便回溯源位置。
3. **自定义语法**：注册两个 `DelimiterProcessor` —— `==高亮==` 与 `$公式$`。
   - 0.30 的接口已改为 `getOpeningCharacter/getClosingCharacter/getMinLength/process(opener, closer): Int`，`process` 返回消费的分隔符数量。
   - 公式做了防误伤：单 `$` 时要求内容首尾非空白、且含非数字字符（`$5`、`$8 元` 不会变成公式）；`$$…$$` 判为独立公式块。
   - `$` 的分隔符 run 在行首/行尾不满足左右 flanking 规则，因此另在段落层面识别整段 `$$…$$`。
4. **AST → 模型**：转成扁平的 `MdBlock` 列表（阅读视图用 `LazyColumn` 按块回收），块内文本转成 `Inline` 树。列表用 `depth` 表达层级而不嵌套组件，避免深层缩进带来的测量开销。
5. **副产品**：标题同时产出目录条目（含块下标，供锚点跳转），并统计中英文字数。

### 任务回写

阅读模式勾选任务时，需要精确改写源文件里的那一个字符：

- 首选 `TaskListItemMarker` 的 `SourceSpan.inputIndex`；
- 该自定义节点在部分路径下拿不到源信息，因此按**行号 + 正则**回退定位 `[ ]`，取 `'['` 的绝对偏移；
- 写回只替换 `markerIndex + 1` 这一个字符（`' '` ↔ `'x'`），不触碰其余文本，随即保存。

## 3. 主题系统（`ui/theme/Theme.kt`）

- 12 个主题族由一组种子色派生：背景、表面、分隔线、三级文字、主色四档（primary / deep / soft / whisper）、代码与语法色。
- 浅色族在深色模式下**派生**深色：保持色相，饱和度压到 7%–26%，亮度抬到 10%–24%，主色提亮，避免直接反色导致刺眼。
- 护眼纸质模式在浅色基础上叠加纸张底色与暖调文字，深色主题下不生效。
- 底纹用 `ImageShader` 以 20dp 为单元格绘制 6 种矢量图案，按装饰档位取 4.5% / 2% / 0% 透明度——不用位图、不进 apk 资源。
- 所有派生结果按 `族|深浅|档位|字号|护眼` 做缓存，切主题即时生效。
- 正文字号可调范围 10–22sp（`SettingsStore.MIN_BODY/MAX_BODY`，设置页滑块直接读这两个常量，不另写死区间）。其余字号都按正文倍数派生，因此在 `typography()` 里加了 10sp 的绝对下限 `MIN_TEXT_SP`：字号 ≥ 12.5sp 时所有派生值都在线下，既有观感不变；只有把正文调到 10–12sp 时，`caption`/`kbd`/`label` 这类辅助文字才会被托住，不会掉到 8sp 那种读不动的尺寸。
- **Material3 1.4 起 `MaterialTheme` 不再代设 `LocalContentColor`**（该 local 的默认值是纯黑）。因此 `ShijianTheme` 显式提供 `LocalContentColor provides spec.colors.onBackground`，阅读区的 `InlineText` 也把 `color` 从可空改为必填、默认 `onBackground`——堵死「静默回退成黑色」这条路：浅色下黑字看着正常，深色下就是黑底黑字。

字号、行高、圆角、页边距、正文列宽上限都收敛在 `ThemeSpec` 里，组件只读令牌，不写死尺寸。

## 5. 编辑器

- `BasicTextField` + `VisualTransformation`：把源码按行着色（标题、引用、列表标记、复选框、链接、行内码、粗斜删高亮、前置元数据、围栏代码），`OffsetMapping.Identity` 保证光标位置不变。
- 插入工具条在光标/选区处做三种操作：包裹（`**粗**`）、行首前缀（`- ` / `> `）、片段插入（代码块、表格）。全部基于 `TextFieldValue` 的纯函数实现。
- 自动保存 1.2 秒防抖；未命名文档写入 `filesDir/draft.md` 并在首页提供「继续上次的草稿」。
- 回顶按钮：阅读与分栏预览共用同一个 `LazyListState`，直接观察 `firstVisibleItemIndex`/`firstVisibleItemScrollOffset`（阈值 160dp）决定显隐，点击 `animateScrollToItem(0)`。源码编辑没有对外暴露的滚动量，改看 `TextFieldValue.selection`——把光标移到文首即可，`CoreTextField` 的 `VerticalScrollLayoutModifier` 会在光标矩形变化时自动把光标滚进可视区（已核对 Compose Foundation 1.12.1 源码）。按钮 44dp 圆形，编辑模式下底部让开 `EditorToolbarHeight`（56dp）并同样带 `imePadding()`，与工具条一起随键盘上移。

## 6. 已知边界（有意为之）

- 远程图片不加载（应用未申请 INTERNET 权限），占位卡提示；本地相对路径按文档所在目录解析。
- 行内图片（段落中间）以 `[图片: 描述]` 占位，独立成段的图片才整幅渲染。
- Mermaid 不做；数学公式 v1 以等宽降级呈现，v1.2 接真渲染。
- 行内所见即所得排在 v1.1，v1 是「源码编辑 + 分栏预览」。
- **外部分享来源只能读**：QQ / 微信 / 钉钉等用 `FileProvider` 分享出来的 `.md` 只带读授权，
  而且不带 `FLAG_GRANT_PERSISTABLE_URI_PERMISSION`，长期授权拿不到（进程一结束就失效）。
  拾简的处理是把内容导入 `filesDir/imports/` 的私有副本再打开：可编辑、可写回、勾选任务也能回写，
  原文件不动，状态栏标「导入副本」，要落地到用户能看见的位置请用「另存为」。
  同一来源再次打开时**复用已有副本且不覆盖**，避免把用户已经改过的副本内容冲掉。
- 最近列表里由旧版本留下的 `content://` 条目（授权已随进程消失）会标「需重新授权」，
  点击时给出可读提示，而不是抛原始 `SecurityException`；条目可用行尾垃圾桶移除。

## 10. 笔记库（v0.2）

### 为什么是「一个普通文件夹」

库根就是一个真实目录（默认内部存储 `Documents/拾简`），App 不建数据库、不做私有副本：

- 电脑连线、云盘同步看到的是同一批文件，用户在电脑上整理目录，手机上打开就是整理后的样子；
- 反过来在 App 里改名、移动、删除，改的也是真文件，不存在「两边不同步」的问题；
- App 只额外保存**附属信息**：阅读进度、收藏、最近打开（`data/RecentStore.kt`）。

### 授权：只问一次

`LibraryGuideScreen` → `ACTION_OPEN_DOCUMENT_TREE` → `takePersistableUriPermission`，
授权存进 `LibraryStore`（SharedPreferences）。之后重启、升级都不会再问。

两个容易踩的点：

1. **用户选的不一定是库根本身**。选到「内部存储」根或 `Documents` 时，`Library.resolveRoot()`
   会在下面建一个「拾简」当逻辑根；所以库记的是两层——`treeUri`（授权凭证）与 `rootDocId`（逻辑根）。
2. **Android 11+ 不允许把「下载」和内部存储根目录整个授权**，`Library.isBlockedPick()` 提前挡住并给出可读提示。

### 目录读取：一次 cursor

`Library.list()` 用 `buildChildDocumentsUriUsingTree` 拿 children uri，再用**一次** query 取回
`DISPLAY_NAME / MIME_TYPE / SIZE / LAST_MODIFIED / DOCUMENT_ID`。不用 `DocumentFile.listFiles()`：
它每个属性都要跨进程问一次 provider，几十个文件就能卡出好几秒。

文件夹行右侧的「N 个文件」角标要额外查子目录，因此给了 **1 秒总预算**（`fillFolderCounts`）——
云端目录慢的时候拿不到就先只显示时间，列表不会停在那里转圈。

### 写权限：库里的文件是「树的后代」

`DocIo.hasPersistedGrant/hasPersistedWrite` 原来只比对 `persistedUriPermissions` 里的 uri 是否**相等**，
而库里的每个文件都是目录树的**后代**，只比对相等会把库里所有文件判成「没权限」，进而退回私有副本
——等于白建库。现在按文档 id 前缀判断（`DocIo.isUnder`）。

写回用 `openOutputStream(uri, "wt")`（唯一「截断 + 写」的模式），个别 provider 不认就依次退到
`rwt` / `w`，遇到 `SecurityException` 立刻停手并报权限错误。

### 导入流程（`AppViewModel.openExternal`）

| 场景 | 行为 |
| --- | --- |
| 文件已在库里 | 直接打开，不留副本 |
| 应用内「新建 → 从本机导入文件」 | 直接落在**当前打开的这个文件夹**，不绕收件箱、也不再问一次 |
| 没设库 + 从 QQ / 微信打开 | 记住待导入文件，先引导选库目录，选完立即导入并打开 |
| 已设库、还没确认过 | 弹一次「收进笔记库吗？」（默认勾选「以后都导入到这里」） |
| 已设库、已确认 | 静默复制进「收件箱」并打开 |
| 导入失败 | 退回老路径（私有副本 / 只读打开），至少不把用户挡在文档外面 |

同名文件自动变成 `名字 (2).md`，不覆盖已有笔记；来源文件名没有可识别后缀时补 `.md`，免得导进来在列表里看不见。

落点是两条路：**外部来源**（QQ / 微信 / 系统分享）没有「用户正站在哪个文件夹里」这个上下文，
统一进「收件箱」等着整理；**应用内导入**是用户在某一个文件夹里主动点的，就把那个目录作为
`PendingImport.targetDir` 传下去 —— 用户要的是「导到这里」，再绕回收件箱就成了 bug。

### 首页结构

首页从「最近打开」改成**库浏览**（`ui/home/LibraryScreen.kt`）：面包屑 + 文件夹在前 + 「继续阅读」卡片；
「最近打开」降级成右上角菜单里的一个入口（`HomeScreen` 加 `onBack`）。平板上留出阅读宽度，靠 `WindowSize` 断点适配。

## 11. 分类整理（v0.2 · M2）

笔记都是先从电脑发到手机、再用「其他方式打开」交给拾简的，所以**收进来之后的归类**比浏览更重要：
库不是只读的目录树，而是一个能就地建文件夹、随手搬家的空间。

### 多选：长按进入，底部一栏批量处理

长按任意一行 → 进入多选（`LibRow` 的 `combinedClickable`），顶栏变成「已选 N 项 + 全选」，
底部 FAB 换成动作栏：移动 / 重命名 / 导出 / 删除（重命名与导出只在选中一项时出现）。
选择状态放在 `LibraryScreen` 的 `remember` 里，**换目录就清空**（`LaunchedEffect(vm.libDirId)`）——
否则会出现「选着的东西已经不在当前列表里」这种看不到的幽灵选择。

### 移动到别的文件夹

`MoveSheet` 是一个迷你浏览器：点文件夹 = 往里走一层，`上一层` 回退，`新建文件夹…` 就地建，
底部按钮把东西搬进**当前这一层**。只保留「点行 = 进入」一个手势，避免「选中」和「进入」互相打架。

移动本身有两个坑，`AppViewModel.relocate` 各处理一个：

1. **重名**：`moveDocument` 在有的 provider 上失败、有的直接覆盖。搬之前先列一次目标目录，
   有重名就回界面上问一句 —— 「都留着」（先 `rename` 成不冲突的名字再搬）或「替换」
   （先 `delete` 目标里的同名文件再搬）。绝不静默覆盖用户的笔记。
2. **移进自己**：文件夹不能搬进它自己或它的子目录（`Library.isUnderDocId` 挡掉），否则整棵子树会消失。

`Library.moveEntry` 还带一层退化：个别 provider 不支持 `moveDocument`，md 文件就退成
「读出来 → 在新位置建一份 → 删原件」；**文件夹不做这种退化**，递归复制再删太危险，宁可如实报失败。

### 删除 = 进回收站，7 天后真删

「删除」实际是把文件 `moveDocument` 进库根的 `.trash/`，同时在 `TrashStore`（SharedPreferences）里记一条
「原来在哪、什么时候删的」。回收站页面能看到每条「原位置：拾简 / 工作 · 剩 5 天」，可还原、可彻底删除、可清空。

过期清理是**惰性**的：启动、换库、进回收站时顺手扫一遍（`purgeTrashQuietly` / `openTrash`），
过期条目直接 `deleteDocument`。没有 `WorkManager`、没有后台任务 —— 清理晚一点没有任何代价，
而常驻定时任务会一直占着电池。

账本和目录两边都可能对不上，所以两条规则兜底：

- **目录里没有的，账本也删**（`retainOnly`）：用户在电脑上手动删了 `.trash` 里的文件，记录跟着走，不留孤儿。
- **账本里没有的，按「刚删除」补一条**（`ensure`）：云盘同步过来的、换设备带过来的文件不会一进回收站就被清掉。

### `docId` 会变，别在移动前记账

内部存储（`ExternalStorageProvider`）的文档 id **就是路径**：`primary:Documents/拾简/x.md`。
移动、改名之后这个 id 立刻不一样，拿移动前算好的 id 记账，将来一定对不上。

所以 `trashOne` 的顺序是：先搬，再 `findChild` 回查一次搬完之后的真实 id，然后才 `mark`。
（Google Drive 这类 id 稳定的 provider 也走同一条路径，只是结果和搬之前一样。）

### `.trash` 是隐藏目录

`Library.list()` 默认跳过 `.` 开头的条目，所以 `.trash` 在浏览器里看不见 —— 但同一个规则也让
`ensureChild` 永远找不到它，于是**每次删除都会再建一个 `.trash`**。修法是给
`list/findChild` 加 `includeHidden` 开关，只有回收站自己的读取路径传 true。

### 平板左侧栏

`EXPANDED`（≥840dp）时左边多一栏（`LibrarySidebar`）：全部笔记 + 库根一级文件夹 + 回收站 + 最近打开 + 设置，
选中项用主色浅底标记。它读的是 `rootFolders`（`refreshRootFolders` 在每次浏览后顺手刷新的一次 cursor 查询），
而不是递归扫整棵树 —— 树在大目录、云盘上会慢到没法用，而一级文件夹已经够用。
