## 1. 项目目标与范围

### 1.1 定位

一个**本地优先**的 Markdown 阅读与编辑应用：

- **阅读**：把 `.md` 渲染成"排版好的文章"，而不是"带标记的代码"；
- **编辑**：源码编辑 + 实时预览，输入体验接近桌面编辑器；
- **适配**：从 5 英寸手机竖屏到 13 英寸平板横屏（含折叠屏、分屏、桌面模式）都不出现错版；
- **离线**：不依赖网络与账号，文件即数据，随时能用别的工具打开。

### 1.2 核心场景

| # | 场景 | 关键要求 |
| --- | --- | --- |
| S1 | 从文件管理器 / 微信 / 邮件"用其他应用打开"一个 .md | 冷启动 < 1s 进入阅读页；不丢原始编码与换行符 |
| S2 | 手机上碎片化阅读长文档 | 大纲跳转、字号缩放、深色 / 护眼、阅读进度记忆 |
| S3 | 平板上编辑并实时看效果 | 分栏预览、外接键盘快捷键、表格与列表输入增强 |
| S4 | 手机上速记或改几行 | 一键进入编辑、工具栏插入语法、自动保存 |
| S5 | 把文章分享出去 | 导出 HTML / PDF / 长图，或分享渲染后的纯文本 |

### 1.3 v1 范围（P0）

- **阅读模式**：CommonMark + GFM 完整渲染（见 5.3 方言表）；
- **编辑模式**：源码编辑 + 语法高亮 + 快捷工具栏 + 撤销 / 重做 + 查找替换 + 自动保存；
- **文件**：SAF 打开、最近文件、另存为、重命名、分享 / "打开方式"接入；
- **主题**：12 个主题族 / 21 组色板（第 7 章）+ 装饰强度三档 + 跟随系统深浅色；
- **适配**：手机 / 平板 / 折叠屏 / 分屏 / 桌面模式，字体缩放 100%–200%，深色模式，横竖屏；
- **导出**：HTML、PDF、PNG 长图。

### 1.4 非目标（v1 明确不做）

- 云同步 / 账号 / 多端协作 / 插件系统 / 双链知识图谱；
- 完整 Typora 级别的**行内 WYSIWYG**（输入时隐去标记）→ 列为 v1.1 试验项；
- Mermaid 图表渲染 → v1 按代码块展示源码，v1.2 再评估；
- LaTeX 数学公式 → 默认 P1，若你确认需要则提到 M1（见 D5）。

### 1.5 成功标准（可验收）

1. 设备 / 分辨率 / 字体缩放 / 主题组合的**截图矩阵**中零错版（无截断、重叠、越界、点击目标错位）；
2. 打开 1MB、2 万行 Markdown：首屏渲染 < 800ms，滚动稳定 60fps；
3. 字体缩放 200% + 深色 + 横屏 + 分屏组合下无破版；
4. 所有内置主题下，正文对比度 ≥ 4.5:1、标题与大字 ≥ 3:1。

### D1｜语言与 UI 框架

- **建议：Kotlin + Jetpack Compose + Material 3。**
- 理由：窗口尺寸分级、折叠屏、多窗口等自适应能力官方支持最完整；声明式 UI 对"同一内容多种布局"的改造成本最低；主题令牌体系与 Compose 天然契合。
- 代价：需要给工程加 Kotlin 与 Compose 插件；你若对 Kotlin 不熟，后续维护曲线略陡。
- 备选：保留 Java + View 体系（RecyclerView + ConstraintLayout）。可行，但自适应与主题切换的代码量约多 40%。

### D2｜Markdown 渲染方式

**原生渲染与 WebView 的实际差异（按本项目会碰到的场景排列）：**

| 场景 | 原生（Compose 渲染） | WebView（HTML/CSS 渲染） |
| --- | --- | --- |
| 系统字体缩放 200% | 全应用自动一致 | 网页不跟随系统，需注入 textZoom，容易出现"部分元素没缩放" |
| 深色模式切换 | 令牌切换即时生效 | 需注入 CSS 变量 / 媒体查询；部分 ROM 强制反色会二次处理网页 |
| 输入法、光标、长按选择 | 系统原生组件，最稳 | `contenteditable` 在 Android 上光标跳动、候选词与选择手柄问题最多 |
| TalkBack 无障碍 | 语义完整（标题、表格、代码块可逐级导航） | 网页语义弱，读屏体验割裂 |
| 冷启动与内存 | 快、可控；长文可分块懒渲染 | WebView 初始化 +100–300ms，常驻内存 50–150MB |
| 滚动手感与手势 | 与系统一致（惯性、overscroll、侧滑返回、嵌套滚动） | 网页自管滚动，与抽屉 / 嵌套滚动易冲突 |
| 文本选择菜单 | 系统菜单，可加入自定义项（如"复制为纯文本"） | 网页菜单，与系统分享 / 翻译集成弱 |
| 主题实现 | Compose 令牌，21 组色板统一管理 | CSS 最接近 Typora，但**跨设备差异最大**（字体回退、单位、渲染引擎版本） |
| 数学公式 / Mermaid | 做不了，需引入库或局部内嵌 WebView | 直接可用（KaTeX / Mermaid） |
| 开发速度 | 较慢：每个 Markdown 元素都要手写 Compose 组件 | 较快：成熟 JS 生态（markdown-it 等） |

**结论**：你的硬性要求是"大部分手机平板都能用、不出现布局与格式不匹配"——这正是 WebView 最弱、原生最强的环节。因此本项目**主体走原生**；唯一例外是未来的数学公式 / Mermaid，用一个**固定尺寸的局部内嵌 WebView** 把它隔离在小区块里，不影响整体一致性。

- **建议：原生渲染** —— `commonmark-java` 解析为 AST，再映射为语义块，用 Compose 渲染；编辑器用自研语法高亮。
- 理由：没有 WebView 的内存与输入法坑；长文档可分块懒渲染；主题、深色模式、字体缩放、无障碍都自然生效。
- 备选：WebView + markdown-it（Typora 的 CSS 可近乎直接复用）。**但这正是"照搬导致不适配"的路径**：WebView 内 rem 缩放、hover、字体回退、深色模式均不受 Android 体系控制。
- 备注：若想快速看视觉效果，可先做一个**仅供内部参考的 WebView 原型**，正式实现仍走原生。

### D3｜编辑形态

- **建议：双模式首发** —— 「阅读」与「编辑（源码 + 高亮）」；平板上支持「编辑 | 预览」分栏实时同步。
- 理由：行内 WYSIWYG 是 Typora 最复杂的部分（光标与标记隐藏的边界情况极多），首发做它会显著拉长工期且稳定性难保证。
- v1.1 试验：基于 `AnnotatedString` 的标记弱化式行内预览。

### D4｜应用名与包名

- 现状：应用名 `md`，包名 `com.example.md`（`com.example` 无法上架）。
- 候选名：**墨笺** / **笺墨** / **拾简**（刻意不与 `phycat` 同名，避免"照搬"观感）。
- 待定：中文名、英文名、包名（建议 `cn.<你的域名>.<appname>`）。

### D5｜首版是否包含数学公式与 Mermaid

**这两个是什么（通俗版）：**

- **数学公式**：文档里写的 `$E = mc^2$` 或 `$$\int_0^1 x^2\,dx = \frac{1}{3}$$`，用 LaTeX 语法描述公式。**支持** = 渲染成真正的数学排版（上标、分式、积分号）；**不支持** = 原样显示这串字符。
- **Mermaid**：在代码块里用文字描述图表，例如 `graph TD; A-->B;`，用来画流程图、时序图。**支持** = 画成图；**不支持** = 显示为普通代码块。

> 重要：这两项"不支持"**不会让文档出错、也不会丢内容**，只是以源码形式展示。区别仅在"好看程度"。

- 建议：数学公式 **P1**（v1 用等宽排版降级显示，v1.2 再上真渲染）；Mermaid **不做**（体积大、移动端体验差）。
- 若你经常写公式，我可以把公式渲染提到 M1。

### D6｜最低支持版本

- **建议保持 minSdk 24**（Android 7.0，覆盖约 98% 在用设备），配合降级策略（见 6.5）。
- 若只在意近 3 年设备，可升到 26/28，能省掉少量兼容分支。

## 5. 技术架构

### 5.1 分层与目录结构

```
app/src/main/java/<pkg>/
├── ui/                    界面层（Compose）
│   ├── theme/             设计令牌、主题加载、装饰强度、代码配色
│   ├── components/        文档元素组件（标题/表格/代码块/任务项/引用…）
│   ├── reader/            阅读页（大纲、字号、进度）
│   ├── editor/            编辑页（源码高亮、工具栏、预览联动）
│   ├── files/             文件与最近列表
│   ├── outline/           大纲抽屉 / 常驻侧栏
│   └── settings/          外观、编辑器、关于
├── domain/                领域层（纯 Kotlin，可单测）
│   ├── model/             MdDocument / MdBlock / Outline / ThemeSpec / RecentFile
│   └── usecase/           打开、保存、导出、统计、格式化
├── md/                    Markdown 引擎
│   ├── parser/            commonmark 配置、方言定义、AST → 语义块
│   ├── highlight/         源码语法高亮
│   ├── toc/               大纲与 [TOC] 构建
│   └── export/            HTML / PDF / PNG 生成
├── data/                  数据层
│   ├── file/              SAF 读写、编码与换行探测、冲突检测
│   ├── settings/          DataStore（主题、字号、默认模式…）
│   └── recent/            Room 最近文件与进度
└── platform/              系统适配（insets、窗口尺寸、折叠铰链、分享、字体下载）
```

依赖方向：`ui → domain ← data`，`md` 被 `domain` 调用且不依赖 Android UI；保证解析与渲染模型可脱离设备做单元测试。

### 5.2 核心数据模型（草案）

```kotlin
data class MdDocument(                 // 文档身份与元信息
    val uri: String,                   // SAF Uri
    val displayName: String,
    val encoding: TextEncoding,        // UTF-8 / UTF-8-BOM / GBK / UTF-16
    val eol: Eol,                      // LF / CRLF / CR（保存时保持原样）
    val lastModified: Long,            // 用于外部修改冲突检测
    val readProgress: Float,           // 0f..1f
)

sealed interface MdBlock {             // 解析后的语义块（UI 无关）
    data class Heading(level: Int, number: String?, inline: List<MdInline>) : MdBlock
    data class Paragraph(inline: List<MdInline>) : MdBlock
    data class CodeBlock(lang: String?, code: String, highlight: HighlightedCode?) : MdBlock
    data class Table(header: List<MdInline>, rows: List<List<MdInline>>, align: List<Align>) : MdBlock
    data class Quote(depth: Int, blocks: List<MdBlock>) : MdBlock
    data class ListBlock(ordered: Boolean, start: Int, items: List<MdListItem>) : MdBlock
    data class TaskItem(checked: Boolean, inline: List<MdInline>, srcLine: Int) : MdBlock
    data class ThematicBreak(val kind: Int) : MdBlock
    data class Image(val src: String, val alt: String, val title: String?) : MdBlock
    data class Toc(val items: List<OutlineItem>) : MdBlock
    data class FrontMatter(val pairs: List<Pair<String, String>>) : MdBlock
    data class FootnoteDef(val label: String, val blocks: List<MdBlock>) : MdBlock
}
```

要点：块级模型**不含任何 Android / Compose 类型**，这样渲染层可以整体替换（例如未来做 WebView 导出），也能让"格式不匹配"问题被单元测试覆盖。

### 5.3 Markdown 方言（AppMDFlavor v1）

这是解决"格式不匹配"的根本手段：**明确支持什么、明确不支持什么、不支持时如何降级**。

| 语法 | 支持 | 说明 / 降级 |
| --- | --- | --- |
| ATX 标题 `#`…`######` | ✅ | 可选自动编号（默认关闭，避免与用户手写编号冲突） |
| Setext 标题（`===` / `---`） | ✅ | 按 H1 / H2 渲染 |
| 段落、硬换行（行尾两空格 / 反斜杠） | ✅ | 两种硬换行都识别 |
| 强调 `*` `_` `**` `__` | ✅ | |
| 删除线 `~~` | ✅ | |
| 高亮 `==…==` | ✅ | 需自定义扩展（Typora 习惯语法） |
| 行内代码、围栏代码块（``` 与 ~~~，含语言标注） | ✅ | 标题栏显示语言 + 一键复制 |
| 链接、图片、引用式链接 | ✅ | 相对路径按文档所在目录解析 |
| 无序 / 有序 / 嵌套列表、列表内多段落 | ✅ | |
| 任务列表 `- [ ]` / `- [x]` | ✅ | 阅读模式点击可回写源文件（默认开启，可在设置关闭） |
| 表格（GFM，含对齐） | ✅ | 超宽横向滚动，首列冻结（P1） |
| 引用块（可嵌套） | ✅ | 嵌套深度用缩进 + 递浅色表示 |
| 分割线 | ✅ | |
| 脚注 `[^1]` | ✅ | |
| YAML Front Matter | ✅ | 默认折叠为「属性」卡片 |
| `[TOC]` | ✅ | 渲染为目录卡片 |
| 行内 HTML | ⚠️ 受限 | 白名单标签（b/i/u/sub/sup/kbd/br），其余按纯文本显示；样式过滤 |
| 数学 `$…$` / `$$…$$` | ⏳ P1 | v1 以等宽文本呈现，不丢字符 |
| Mermaid / 流程图 | ❌ | 按代码块展示源码 |
| 未知 / 专有语法 | —— | **原样文本输出**，绝不丢字符、不报错 |

编码与换行：默认 UTF-8；探测 BOM；可识别 GBK / GB18030 / UTF-16 并**按原编码保存**；CRLF 与 LF 原样保留（仅内部统一为 LF 处理，写回时还原）。

### 5.4 渲染管线（阅读模式）

1. 文件 → 文本（编码探测、换行归一）
2. 文本 → AST（commonmark-java + 方言扩展）
3. AST → `List<MdBlock>`（纯 Kotlin，可单测）
4. `MdBlock` → Compose（`LazyColumn` 分块懒渲染）
   - 段落内部用 `AnnotatedString` 一次性构建样式，避免嵌套 Composable 过多；
   - 代码高亮在后台线程完成，先出纯文本再回填彩色；
   - 图片用 Coil 异步加载，`content://` 相对路径按文档目录解析。
5. **增量**：编辑时按空行分段做脏标记，只重解析与重绘受影响的块，避免整篇重排。

性能策略：解析在 `Dispatchers.Default`；块高缓存；超长文档（> 2 万行）启用"仅渲染可视区 + 高度预估"。

### 5.5 编辑管线

- 文本状态：单 `TextFieldValue`，大文档用增量快照，避免每次按键全量复制字符串；
- 高亮：行级状态机（标题 / 引用 / 围栏 / 行内标记），只处理可视区域；
- 撤销 / 重做：自建 undo 栈，按"输入批次 + 时间阈值"合并；
- 输入增强：列表自动续行、Tab / Shift-Tab 缩进、表格 Tab 跳格、成对符号自动补全；
- 查找替换：全部匹配高亮 + 上/下一个 + 替换 / 全部替换（大小写、全词可选）；
- 自动保存：停止输入 1s 后写回；`openOutputStream(uri, "wt")`，支持时先写临时再替换；
- 冲突：比对 `lastModified`，外部被改动时提示"文件已被其他应用修改"，提供覆盖 / 另存为。

## 6. 自适应与兼容性设计

这是"不要出现布局问题"这一要求的落地章节，也是本项目最重要的工程约束。

### 6.1 窗口尺寸分级与布局矩阵

按 Material 3 窗口尺寸分级（以**窗口宽度**为准，而非屏幕宽度——这样分屏、小窗、桌面模式自动正确）：

| 分级 | 宽度 | 典型形态 | 布局 |
| --- | --- | --- | --- |
| Compact | < 600dp | 手机竖屏、折叠屏外屏、分屏小窗 | 单栏（阅读 **或** 编辑），顶栏切换模式；大纲为抽屉；底部浮动工具条 |
| Medium | 600–839dp | 手机横屏、小平板竖屏、折叠屏内屏 | 可选双栏：编辑 55% \| 预览 45%，分隔条可拖动；大纲可作为窄侧栏 |
| Expanded | ≥ 840dp | 平板横屏、桌面模式、自由窗口 | 三栏：大纲 240dp \| 编辑 \| 预览；正文列宽上限 720dp 居中 |

高度维度附加规则：

- 高度 < 480dp（横屏手机、键盘弹起后）：顶栏压成单行、底部工具条收进溢出菜单、段间距 -20%；
- 高度 ≥ 900dp：阅读模式可双页并排（P1）。

形态适配：

- **折叠屏**：用 `WindowLayoutInfo` 的 `FoldingFeature` 判断铰链位置，关键内容不落在折叠/铰链区；展开与折叠切换时保持滚动位置与光标；
- **多窗口 / 自由窗口**：`resizeableActivity` 保持默认 true，窗口尺寸变化时按分级重排；状态放 `ViewModel` + `rememberSaveable`，不因旋转/改尺寸重建丢失；
- **桌面模式（DeX / PC 模式）**：支持鼠标滚轮、右键菜单、外接键盘快捷键。

### 6.4 边界场景清单

内容侧（每一条都要有对应的自动化或手工用例）：

1. 超长 URL / 无空格长串 → 强制断行，绝不撑破容器；
2. 宽表格 → 横向滚动；窄屏可选"卡片化"降级（P1）；
3. 代码块长行 → 横向滚动（默认不折行），可切换软换行；
4. 超大图 / 超长图 → 宽度 100%，长图全屏查看，避免一次性解码 OOM（按需采样）；
5. 图片加载失败 / 无权限 → 占位图 + 路径提示，不崩不白屏；
6. 空文档 / 纯空白 → 空态提示；
7. 中英日阿混排（RTL）→ 遵循 Unicode 双向算法；代码块与链接强制 LTR；
8. Emoji / 组合字符 / 零宽字符 → 不破坏行高与光标定位；
9. 深层嵌套（引用 / 列表 ≥ 3 层）→ 总缩进上限 24dp，超出后改为颜色弱化而不是继续缩进；
10. 单行超长标题 → 阅读模式正常折行；顶栏标题省略号显示。

系统侧：

11. **字体缩放 200%** → 全部尺寸用 sp；标题容器不固定高度；工具栏图标与文字不重叠、不截断；
12. **横屏矮屏** → 工具栏压缩；键盘弹起后当前编辑行仍可见（IME insets + 自动滚动）；
13. **分屏 / 自由窗口** → 320dp 极窄宽度下仍可用（工具栏图标折叠为二级菜单）；
14. **深色模式切换（含系统强制深色）** → 立即生效不闪白；无 WebView，因此不存在 force-dark 二次反色问题；
15. **RTL 语言** → UI 镜像，源码编辑区保持 LTR；
16. **外接键盘 / 手写笔 / 鼠标** → 快捷键 Ctrl+S/B/I/K、Ctrl+F、Ctrl+Z；鼠标 hover 只做轻量反馈，不作为唯一交互路径；
17. **旋转 / 进程死亡恢复** → 光标位置、滚动位置、未保存内容全部恢复。

## 7. 主题系统设计（核心章节）

> 目标：让阅读质感接近你给的 Typora 主题家族，但每一个像素都由我们为触屏重新定义。

### 7.1 设计原则

1. **语义化令牌**：不写死颜色，所有样式走 token；深浅色只是换一套令牌值；
2. **装饰服务于层级**：层级首先靠字号 / 间距 / 颜色权重表达，装饰只做强化；
3. **触屏优先**：不用 hover 承载信息；动效只做"按下 / 进入"反馈，时长 ≤ 200ms；
4. **对比度优先于美观**：正文 ≥ 4.5:1，标题与大字 ≥ 3:1；
5. **低功耗**：静态纹理、无常驻动画、无实时模糊（除非 API 31+ 且用户选了"完整"档）；
6. **可降级**：装饰强度三档，最弱一档只有排版、没有装饰。

### 7.2 不照搬清单（原做法 → 问题 → 我们的做法）

| # | Typora 原做法 | 为什么不照搬 | 移动端做法 |
| --- | --- | --- | --- |
| 1 | 直接复用 CSS（`#write`、`.md-fences` 等） | Android 没有这套 DOM；rem / hover / 字体回退全部不可控 | 全部用 Compose 令牌重写 |
| 2 | 11 处 hover 动效：标题上浮、图片放大、链接图标旋转 180°、引用缩放 | 触屏无 hover，手势还会误触 | 改为静态样式；重要反馈放到点击态 |
| 3 | `#write::before` 用 12% 主题色纹理遮罩整页 | 手机上过重、干扰阅读；遮罩层重绘开销 | 降到 **2%–4%**，仅"完整"档开启；用矢量纹理平铺着色绘制 |
| 4 | H2 = 橙色渐变底 + 白字（#ff9f68 → #ff6b35） | 对比度约 2.8:1，**不达标**，小屏更明显 | 浅底深字，或深色底白字，确保 ≥ 4.5:1 |
| 5 | 用 emoji（✨）当引用图标 | 各 ROM emoji 字形/字重差异大，跨机不一致 | 自绘矢量图标 |
| 6 | 打包 SourceHanSerifCN（14MB×2）与 HarmonyOS woff（5.6MB×2） | 包体增加近 40MB | 系统字体优先 + 可选运行时下载 |
| 7 | 正文行高 2.25、字距 1.1px | 手机上每屏仅约 13 行；中文加字距破坏排版 | 行高 1.70–1.75、字距 0 |
| 8 | `backdrop-filter: blur(20px)` 毛玻璃（TOC / 侧栏） | API < 31 无模糊；实时模糊耗电、掉帧 | 半透明底 + 1dp 描边；31+ 且"完整"档才启用真模糊 |
| 9 | 代码块顶部 macOS 红黄绿圆点 | 纯装饰且不可点，占位置 | 改为"语言标签 + 复制按钮" |
| 10 | 标题自动编号默认开启（counter） | 与用户手写编号冲突，阅读时显得喧宾夺主 | 默认关闭，设置中可开 |
| 11 | 任务勾选脉冲动画、hover 展开分割线、`strong` 位移放大 | 滚动时反复触发重绘，耗电且掉帧 | 去掉动效，用状态色 + 删除线表达 |
| 12 | 原暗色主题仍沿用浅色结构、背景 #222 | 深色下 2.25 行高显得更松散，纯灰底对比偏硬 | 深色独立设计：降饱和、非纯黑底（OLED 主题除外）、行高与间距单独调 |

### 7.3 从 phycat 提炼的 6 条设计语言（保留"味道"，不保留实现）

| # | 设计语言 | Typora 原实现 | 我们的重构 |
| --- | --- | --- | --- |
| 1 | **层级化标题** | H1 居中 + 短下划线；H2 实心胶囊；H3 左竖条；H4 实心圆点；H5 空心圆点；H6 短横 | 完整保留这套几何关系（移动端辨识度极高），去掉 hover 与高饱和渐变 |
| 2 | **卡片化块元素** | 引用 / 代码块 / 表格 / YAML / TOC 都是圆角卡片 | 统一 12dp 圆角 + 1dp 描边 + 极浅底色，形成"块与块的呼吸感" |
| 3 | **细装饰线** | H3 竖条 5–7px、H4 圆点 10px、表头浅底、kbd 立体键帽 | 保留全部元素，尺寸按 dp 重定（竖条 3dp、圆点 8dp、键帽高 22dp） |
| 4 | **低饱和纹理背景** | 交叉斜线 / 网格 / 星点 / 六边形 / 三角 / 圆点，12% 主题色 | 保留 6 种纹理种类，透明度降到 2%–4%，只做"纸纹"级存在感 |
| 5 | **玻璃质感** | 半透明白 + 大圆角 + 柔阴影 + 20px 模糊 | 浅色用"表面色 + 描边"；深色用"提亮 3% 的表面色"分层 |
| 6 | **四级强调色** | `element-color` / `-deep` / `-shallow` / `-soo-shallow` | 重构为 `primary` / `primaryDeep` / `primarySoft` / `primaryWhisper` 四级令牌（这是原主题最值得借鉴的一点） |

### 7.4 设计令牌（Token）体系

| 组 | 令牌 | 说明 |
| --- | --- | --- |
| 基础色 | `background` / `surface` / `surfaceVariant` / `surfaceContainerHigh` / `outline` / `outlineVariant` | 页面底、卡片底、分区底、描边 |
| 文字色 | `onBackground` / `onSurface` / `onSurfaceVariant` / `textMuted` | 正文 / 次级 / 弱化 |
| 强调色 | `primary` / `onPrimary` / `primaryDeep` / `primarySoft` / `primaryWhisper` | 四级，与 7.3 第 6 条对应 |
| 功能色 | `link` / `linkVisited` / `success` / `warning` / `danger` | 链接与状态 |

### 7.9 对比度与无障碍

- 正文 / 次级文字 / 链接：≥ 4.5:1；
- 标题与大号文字（≥ 18sp 或 14sp 加粗）：≥ 3:1；
- 装饰（点、线、纹理）不承载信息，允许低对比；
- 复选框、开关等控件：选中态与未选态差异 ≥ 3:1，并提供非颜色线索（对勾 / 形状）；
- 全应用支持 TalkBack：标题用 `heading()` 语义，代码块、表格、任务项提供内容描述；
- 支持系统"减少动画"：此时所有过渡置 0；
- 字号缩放 200% 时不出现截断（见 6.4 第 11 条）。

### 7.10 主题加载与切换

- 主题选择持久化在 DataStore（`themeId`、`darkMode: system/light/dark`、`decorationLevel`、`eyeCarePaper`）；
- 跟随系统时，浅色主题自动映射到它的派生深色色板（7.5 派生规则）；
- 切换动画：仅 200ms 颜色过渡（`animateColorAsState`），"减少动画"时瞬时切换；
- 主题预览：设置页给出缩略图卡片（用同一份 Token 渲染一小段示例文档，所见即所得）；
- 与 Material You 动态取色的关系：**可选**，作为"石墨"族的可选开关；不覆盖品牌主题，避免 21 套色板被系统壁纸冲淡；
- 未来支持"导入 / 导出主题 JSON"，格式与 7.7 一致。

### A.4 发现的问题（"不照搬"的直接理由）

1. **对比度不足**：H2 用 `#ff9f68 → #ff6b35` 渐变底 + 白字，对比度约 2.8:1，低于 4.5:1 标准；小屏上更明显。
2. **hover 依赖**：33 处 hover 动效是这套主题的"手感"来源，但触屏上 100% 失效，且部分动效（图片放大、引用缩放）在触屏会变成误触。
3. **纹理过重**：12% 主题色纹理铺满正文底，在 6 英寸屏幕上会明显干扰阅读，且遮罩层每次重绘都有开销。
4. **字体体积**：近 38MB 的字体资产。
5. **单位与场景错配**：全文 rem/em + 打印样式写死 A4（21cm × 29.7cm），在手机上无法直接映射。
6. **深色是"换色"，不是"重设计"**：`phycat.dark.css` 复制了浅色结构（1213 行 vs 1793 行），行高与间距在深色下未重新优化，页面底用 `#222`。
7. **代码块 bug**：`.cm-s-inner.CodeMirror { background-color: #fa0303; }` 是明显的笔误（亮红色），被后文的 `background: #f8f8f8` 覆盖才没暴露。
8. **平台专属 DOM**：`.md-fences`、`.CodeMirror`、`#write`、`.md-toc` 等选择器只在 Typora 里存在。
9. **装饰性元素不可点**：代码块的 macOS 红黄绿圆点是纯装饰；emoji 图标（✨）在不同 Android ROM 上字形差异大。
10. **格式漂移**：个别变量值跨多行（如 mint 的渐变），说明文件是长期手写演进的，直接解析风险高。

### A.5 结论

| 可以借鉴（已进第 7 章） | 必须重做 |
| --- | --- |
| 四级强调色体系 | 全部色值（按移动端对比度重算） |
| 层级化标题的几何语言（居中 H1 / 胶囊 H2 / 竖条 H3 / 点 H4–H6） | 尺寸单位与排版参数（dp/sp 重定） |
| 6 种纹理的种类与"淡淡一层"的思路 | 透明度（12% → 2%–4%）与实现方式 |
| 卡片化块元素 + 柔阴影 | 模糊策略（按 API 与性能降级） |
| kbd、任务列表、表格等元素的形态 | 全部 hover 动效改为静态或点击反馈 |
| 亮 / 暗成对、按色系命名的组织方式 | 字体资产（改为系统字体 + 可选下载） |
